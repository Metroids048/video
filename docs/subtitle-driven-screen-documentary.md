# 字幕驱动的录屏专题制作规范

本规范适用于真人口播 + 录屏/产品界面类视频。目标不是“能渲染 MP4”，而是让口播、证据和镜头在同一条时间轴上工作。

## 唯一主时钟

1. 先确定用户真人声音母带，从中选出完整、自然的 20-30 秒试片口播；完整母带不是成片时长。
2. 用 Whisper / video-use 生成句级与词级转写，并产生语义切分的 SRT。
3. SRT/词级时间戳是旁白、字幕、ROI 切换、关键词动效和音效的唯一主时钟。
4. 完整成片必须先通过一个可播放、可检查、可返工的 20-30 秒试片；试片通过后再扩展，不得直接拼接 60-100 秒“最终版”。

## 录屏专题的素材规则

- 真人口播决定“说什么”；参考成片决定可继承的视觉语言与页面顺序；原始录屏是可重排、裁切、放大的真实画面池。
- 缺少与新口播逐句同步的完整录屏不是缺素材，也绝不是 BLOCKED 理由。
- 每个旁白段必须绑定：`segment_id`、真实来源、源时间、`evidence_id`、ROI、字幕安全区、视觉意图和 `max_hold_seconds`。
- 没有完美同句画面时，依次使用最相关真实页、参考成片相关镜头、同页不同 ROI、短 freeze 或真实 UI 上的短关键词。不得生成假交易界面或拿无关画面凑时长。

## 试片和审片

- 试片长度为 20-30 秒，使用真人口播，绝不使用 AI 配音或声音克隆补位。
- 审片人必须实际观看 MP4 并查看联系表/关键帧，评分记录写入 `reviewed_artifacts`。一名可追溯的真实审片人即可启动返修；额外审片人是加分项，不是无故阻塞条件。
- 程序只能生成审片包和确定性指标，不能自己写出 `PASS` 分数。
- 试片未通过只允许按 finding 做一次定向返修；不能在未看成片时无限重写脚本。

## 视觉节奏

- 主画面只放关键词、短语、数字和必要高亮；完整句子留给字幕。
- 口播说到一个信息时，该信息才进入画面。禁止每页内容一次性铺满。
- 录屏镜头超过 4 秒必须产生真实信息增量：ROI 切换、局部放大、滚动、鼠标操作或有证据意义的页面切换。
- 横屏 UI 可保留 16:9。若强做 9:16 会让账号、订单、仓位或历史不可读，优先可读性；同一页面可使用“全页建立场景 → ROI 证据”而不是把横屏缩成小条。

## 工具路由

- `video-use` / Whisper：转写、词级时间戳、SRT、EDL。
- ChatCut：本机已登录时优先用于口播剪辑、时间线和可视审阅。
- Remotion 或 HyperFrames：只做由 SRT 驱动的微动效、关键词和包装；不承载整条录屏专题。
- FFmpeg：确定性的代理生成、ROI 片段、混音、字幕烧录和最终装配；不能作为“静态字幕拼接片”的创作默认。

## 交付门禁

发布包必须同时具备：可解码最终 MP4、通过技术 QA、当前视频哈希对应的 Creative Review、真实审片身份、`reviewed_artifacts`、有效评分和 Creative Gate PASS。任一缺失只表示未完成，不能写为交付完成。
